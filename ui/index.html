Set up an evaluation process
  1. Define an action’s output contract with a gate and optional schema.
  2. Add a model judge for semantic criteria; calibrate it against human-labeled examples before trusting its score.
  3. Add top-level QA to review the whole run. Keep its criteria separate from the generator.
  4. Strictly validate, run one canary, and inspect every result. Compare changes on fixed inputs and a held-out set before promoting them.

Edit the source YAML; evaluation settings apply to future runs. A completed run keeps its frozen contract.

steps:
  - id: draft
    prompt: "Produce the requested artifact from {input}"
    gate: 'test -s "$OUT"' # Replace with a task-specific assertion
    judge:
      model: openai-codex/gpt-5.6-terra
      prompt: 'Apply your frozen rubric to {out}. Return {"score": N, "feedback": "evidence"}.'
      score: 8.5
      max_iters: 1
qa:
  model: openai-codex/gpt-5.6-terra
  prompt: 'Check the run against your frozen acceptance criteria. Return {"verdict":"pass|fail","issues":[]}. {artifacts}'

This is a configuration sketch, not a calibrated rubric. Replace the criteria and gate before running. Judges and QA make additional model calls.

piw validate path/to/steps.yaml --strict --json
piw run path/to/steps.yaml --input-file case.txt --json
piw detail path/to/steps.yaml RUN_ID --step draft --io --json
piw compare path/to/steps.yaml BASELINE_RUN CANDIDATE_RUN --json
